# 유레 대시보드 — 계획 v3 (누구나 쓰는 웹 서비스)

> **목표**: 앱 접속 → 유니온 ID + 서버 선택 → 끝. 설치·설정·로그인 없음
> **원본 대비**: 기능은 nikkeRaid 수준 유지, **사용자 부담은 0**
> **스택**: Supabase(DB·크론·수집기) + Vercel(Next.js) · 월 $0

---

## 1. 무엇이 달라지는가

| | 원본 nikkeRaid | 우리가 만들 것 |
|---|---|---|
| 사용자가 할 일 | Tampermonkey 설치 → GAS 배포 → URL·길드ID·SECRET 입력 | **ID 2개 입력** |
| 대상 | 우리 길드 하나 | **모든 길드** (멀티테넌트) |
| 수집 주체 | 각자 브라우저 | **서버 1곳이 대신** |
| 진입 장벽 | 개발 좀 아는 총무만 | 아무나 |

즉 **인증·수집의 부담을 사용자에게서 서버로 전부 옮기는 것**이 이 프로젝트의 본질입니다.

```
  사용자              우리 서버                블라블라링크
   │  유니온ID 28517
   │  서버 한국(83)
   ├───────────────▶  ┌──────────────┐
                      │ 등록된 길드?  │
                      │  Yes → 즉시   │
                      │  No  → 수집   ├──── 서비스 계정 세션으로 조회
                      └──────┬───────┘
                             ▼
                        Postgres 캐시
                             │
   ◀─────────────────────────┘
   대시보드 (딜순위·미참여·조합·추이)
```

## 2. 🔴 이 서비스의 성립 여부를 가르는 단 하나의 질문

> **"내가 속하지 않은 길드의 ID를 넣어도 API가 데이터를 주는가?"**

- **준다** → 서비스 계정 하나로 전 길드 조회 가능. **사용자는 정말 ID만 입력하면 끝.** 원하시는 그림 그대로 성립
- **안 준다** → 길드마다 소속원 1명이 최초 1회 인증해줘야 함 (아래 3-B로 폴백)

### 지금 바로 확인하는 법 (2분)

블라블라링크 로그인 상태에서 유레 페이지 → `F12` → **Console** 탭에 붙여넣고 엔터:

```js
fetch('https://api.blablalink.com/api/game/proxy/Game/GetUnionRaidDataOfGuildSeason', {
  method: 'POST',
  credentials: 'include',
  headers: {
    'content-type': 'application/json',
    'x-channel-type': '2',
    'x-language': 'ko',
    'x-common-params': '{"game_id":"16","area_id":"global","source":"pc_web","intl_game_id":"29080","language":"ko","env":"prod"}'
  },
  body: JSON.stringify({
    area_id: 83,
    guild_id: '다른길드ID를여기에',   // ← 우리 길드 말고 남의 길드 ID
    season_id: '1000039'
  })
}).then(r => r.json()).then(j => console.log(j));
```

**판정**
- `data.participate_data`에 배열이 차 있으면 → ✅ **성립** (3-A로)
- `code`가 0이 아니거나 권한 오류 → ❌ (3-B로)

> 남의 길드 ID는 **유니온 스퀘어**에서 아무 길드나 눌러보면 URL이나 요청에 나옵니다.

## 3. 두 갈래 설계

### 3-A. 성립할 경우 — 원하시는 그림 그대로 ✅

**서비스 계정 1개**(전용 부계정 권장)의 세션을 서버가 보유하고, 모든 조회를 대행합니다.

- 사용자: ID 2개 입력 → 끝. 영원히 아무것도 안 함
- 길드별 URL `/u/83/28517` → 북마크·공유·단톡방에 던지기 가능
- 처음 보는 길드면 "수집 중… 30초" 표시 후 자동 진입

**쿠키 관리는 운영자(보라님) 몫 하나로 축소됩니다.** 만료되면 북마클릿 1클릭. 사용자 32명이 아니라 보라님 1명만 신경 쓰면 돼요.

### 3-B. 성립 안 할 경우 — 길드당 1회 온보딩

- 길드원 **아무나 1명**이 최초 1회, 유레 페이지에서 북마클릿 클릭 → 그 길드가 서비스에 "연결됨"
- 이후 그 길드원 **전원**은 ID만 입력하면 봄. 설치도 로그인도 없음
- 연결한 사람의 세션이 만료되면 → 그 길드 아무나 다시 1클릭 (앱이 알려줌)

원하신 "ID만 입력"이 **길드당 딱 한 번의 예외**를 빼면 그대로 유지됩니다. 32명 중 31명은 아무것도 안 해요.

## 4. 멀티테넌트 데이터 모델

v2 스키마에 **길드 축**이 추가됩니다.

```sql
create table guilds (
  area_id     int  not null,          -- 81 일본 / 82 북미 / 83 한국 / 84 글로벌 / 85 동남아
  guild_id    text not null,
  name        text,
  member_count int,
  first_seen   timestamptz default now(),
  last_viewed  timestamptz,           -- 크론 우선순위의 핵심
  last_synced  timestamptz,
  sync_state   text default 'pending',-- pending | syncing | ok | auth_required | dead
  primary key (area_id, guild_id)
);

create table attacks (
  id bigserial primary key,
  area_id int not null, guild_id text not null,     -- ★ 추가
  season int, day int, step int, difficulty int, level int,
  boss text, element text,
  openid text not null, nickname text, sync_lv int,
  total_damage bigint not null, is_final_hit boolean,
  squad jsonb not null,
  captured_at timestamptz default now(),
  unique (area_id, guild_id, season, day, openid, boss, total_damage)
);
create index on attacks (area_id, guild_id, season, day);
create index on attacks using gin (squad);

-- members / boss_levels 도 동일하게 (area_id, guild_id) 를 앞에 붙임
-- nikkes / season_coef 는 전역 공유 (길드 무관)
```

### 크론 전략 — 전 길드를 5분마다 돌면 터집니다

**우선순위 큐**로 갑니다.

| 길드 상태 | 갱신 주기 |
|---|---|
| 지금 누가 보고 있음 (`last_viewed` < 10분) | 5분 |
| 최근 3일 내 조회됨 + 유레 기간 | 30분 |
| 그 외 등록 길드 | 6시간 |
| 90일간 아무도 안 봄 | 중단 (`dead`) |

한 사이클에 처리할 길드 수를 상한(예: 20개)으로 묶고, 오래된 순으로 돌립니다. 사용자가 앱을 열면 그 길드는 즉시 큐 맨 앞으로.

## 5. 사용자 경험 설계

```
┌─────────────────────────────┐
│      유레 전적 검색           │   ← 랜딩. 딱 이것만
│                             │
│  서버  [ 한국 ▾ ]            │
│  유니온 ID [  28517      ]   │
│                             │
│        [  조회  ]            │
│                             │
│  최근 본 길드: 미인 · …       │   ← localStorage
└─────────────────────────────┘
            ↓
┌─────────────────────────────┐
│ 미인 (32/32)      🕐 2분 전   │
│ ─────────────────────────── │
│ [개요] [조합] [추이]          │
│                             │
│  40차 · Day 2 (HARD)        │
│  총딜 1.2T   진행 6/10       │
│                             │
│  ⚠ 미참여 3명                │
│    블라비 · 유티콘 · 물거품    │
│  ───────────────────────    │
│  1  피어레스   50.501B  3/3  │
│  2  던창       45.689B  3/3  │
│  3  주디       45.119B  3/3  │
└─────────────────────────────┘
```

- **URL이 곧 상태**: `/u/83/28517?season=40&day=2` → 공유하면 같은 화면
- **로그인 없음**. "내 길드"는 localStorage에 기억
- 첫 조회 시 스켈레톤 + "수집 중" 진행률

## 6. 리스크 — 서비스화하면 새로 생기는 것들

| 리스크 | 대비 |
|---|---|
| **서비스 계정 밴** (3-A) | 전용 부계정 사용, 요청 간격 확보, 캐시 적극 활용. 본계정 절대 사용 금지 |
| **요청량 폭증** | 우선순위 큐 + 길드당 최소 갱신 간격 강제 + 조회 안 되는 길드 자동 은퇴 |
| 남의 길드 데이터 공개 | 이미 게임 내 공개 정보지만, 길드가 원하면 **비공개 전환** 옵션 제공 |
| API 스펙 변경 | 파싱 방어적으로, 실패 시 `sync_state='dead'`로 격리해 전체가 안 죽게 |
| 서비스 약관 | 개인 도구보다 노출이 큼. 비상업·팬툴 성격 명시, 과도한 폴링 금지, 요청 시 차단 대응 |
| Supabase 무료 한도 | 500MB. 길드당 ~20MB(40차 기준) → **25길드**가 한계. 넘으면 오래된 시즌 아카이빙 or 유료 전환 |

> 💡 25길드 한계는 실제로 곧 닿습니다. 시작은 무료로 하되, "시즌 12차 이전은 요약만 보관" 같은 정리 정책을 Phase 5에 넣어둡니다.

## 7. 단계별 실행

### Phase 0 — 성립 검증 ★블로커 (보라님 10분)

### Phase 1 — 기반 (제가, 반나절)

- [ ] RLS: 세션·운영자 테이블 완전 차단, 데이터는 읽기 공개

### Phase 2 — 수집 엔진 (2일)
- [ ] Edge Function: 길드 1개 전체 수집 (정산 시즌 + 진행 시즌 + 보스HP + 명단)
- [ ] 우선순위 큐 + pg_cron
- [ ] 온디맨드 수집 API (신규 길드 조회 시 즉시 실행)
- [ ] 401 감지 → `auth_required` 격리 + 운영자 알림

### Phase 3 — 이미지 CDN (반나절)
- [ ] 니케 398 + 보스 65장 → GitHub → jsDelivr

### Phase 4 — 대시보드 (5~6일)
- [ ] 랜딩 (서버·ID 입력, 최근 본 길드)
- [ ] **개요** — 총딜·진행률·보스카드 / 딜순위·기여도 / **미참여 체크**

- [ ] **시즌 추이** — 차수별 총딜, 개인 성장, 비교
- [ ] 운영자 화면 (보라님 전용) — 세션 갱신, 길드 큐 상태, 계수 편집

### Phase 5 — 운영 (1~2일)
- [ ] Vercel 배포 + 도메인
- [ ] 용량 정리 정책, 백업
